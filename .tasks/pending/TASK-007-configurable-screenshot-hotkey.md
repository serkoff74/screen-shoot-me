# TASK-007 — Настраиваемый глобальный hotkey для запуска снимка

## Контекст и ограничение платформы

Пользователь хочет запускать Snapmark привычной системной комбинацией, например `Ctrl+Insert`, вместо нативного инструмента снимков Ubuntu.

Расширение Chrome может зарегистрировать `Ctrl+Insert` как команду, пока Chrome в фокусе. Но оно не может надёжно перехватить сочетание, уже захваченное Ubuntu или другим приложением: системные shortcuts имеют приоритет. Глобальные команды Chrome поддерживаются с ограничениями, а настройки горячих клавиш расширений доступны пользователю в `chrome://extensions/shortcuts`.

По умолчанию Ubuntu назначает запуск инструмента снимков на `Print`; `Ctrl+Insert` не входит в стандартный набор. Если оно открывает нативное окно у конкретного пользователя, это, вероятно, локальная настройка GNOME, другого DE или стороннего приложения.

## Варианты решения для груминга

1. **Горячая клавиша в фокусе Chrome.** Зарегистрировать `Ctrl+Insert` как допустимую команду расширения; при конфликте пользователь освобождает системный shortcut.
2. **Глобальная команда Chrome.** Предложить поддерживаемый глобальный shortcut и дать пользователю переназначить его в настройках Chrome; проверить фактическое поведение на Linux.
3. **Системная интеграция.** Отдельный нативный companion/helper, который назначается через настройки Ubuntu и передаёт запуск расширению. Это отдельная крупная функция с установкой, разрешениями и поддержкой дистрибутивов.

## Согласованное решение

- Используется команда расширения Chrome с предложенной комбинацией `Ctrl+Insert` (`Command+Shift+S` на macOS).
- Пользователь назначает или меняет сочетание в `chrome://extensions/shortcuts`; текущий статус отображается на странице настроек Snapmark.
- Поддерживается запуск только при фокусе Chrome. Системный helper и произвольный глобальный hotkey не входят в эту задачу.
- `PrintScreen` нельзя назначить командой Chrome (клавиша не входит в допустимые и требует `Ctrl`/`Alt`), поэтому он ловится best-effort в content script, когда клавиша доходит до страницы; для этого пользователь освобождает системное сочетание. Если DE перехватывает клавишу — запуск не сработает, это ограничение платформы.

## Вопросы для груминга

- Целевой сценарий — только при открытом и активном Chrome или из любого приложения?
- Нужно ли поддерживать только Ubuntu GNOME или другие DE и Linux-дистрибутивы?
- Готов ли пользователь вручную отключать конфликтующий системный shortcut?
- Нужен ли отдельный нативный helper, если запуск из любого приложения является обязательным?
- Как показывать конфликт и подсказку о переназначении в `chrome://extensions/shortcuts`?

## Критерии приёмки

- В документации и интерфейсе явно разделены режимы «в фокусе браузера» и «глобальный».
- Поддерживаемая комбинация запускает Snapmark без конфликтов, когда Chrome имеет фокус.
- При конфликте с ОС приложение не обещает невозможного перехвата и показывает понятную инструкцию по смене сочетания.
- Если выбран нативный helper, он устанавливается и отключается безопасно, а сценарий покрыт тестами на целевой платформе.
