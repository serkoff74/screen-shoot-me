# TASK-007 — Настраиваемый глобальный hotkey для запуска снимка

## Контекст и ограничение платформы

Пользователь хочет запускать Snapmark привычной системной комбинацией `Ctrl+PrintScreen` вместо нативного инструмента снимков Ubuntu.

Расширение Chrome не может назначить `Ctrl+PrintScreen` командой: клавиша `PrintScreen` не входит в поддерживаемые keys commands API (там только буквы, цифры, `Comma/Period/Home/End/PageUp/PageDown/Space/Insert/Delete`, стрелки, медиа-клавиши и F1–F12, и команда обязана содержать `Ctrl` или `Alt`). Сочетание, захваченное Ubuntu или другим приложением, тем более не доходит до страницы: системные shortcuts имеют приоритет. Поэтому Snapmark ловит комбинацию best-effort в content script, когда она доходит до страницы.

Ubuntu/GNOME по умолчанию держит `PrintScreen` (снимок экрана), `Alt+PrintScreen` (снимок окна) и `Ctrl+PrintScreen` (копирование экрана в буфер). Чтобы Snapmark получил комбинацию, пользователь освобождает `Ctrl+PrintScreen` в системных настройках; иначе DE перехватит её раньше страницы.

## Варианты решения для груминга

1. **Горячая клавиша в фокусе Chrome через content script.** Ловить `Ctrl+PrintScreen` на странице; при конфликте пользователь освобождает системный shortcut.
2. **Глобальная команда Chrome.** Отклонено: `PrintScreen` не поддерживается commands API, а глобальные команды ограничены `Ctrl+Shift+[0..9]`.
3. **Системная интеграция.** Отдельный нативный companion/helper, который назначается через настройки Ubuntu и передаёт запуск расширению. Это отдельная крупная функция с установкой, разрешениями и поддержкой дистрибутивов.

## Согласованное решение

- Основная горячая клавиша — `Alt+Insert`: обычная команда Chrome (`Insert` входит в поддерживаемые keys commands API), работает, пока Chrome в фокусе; меняется в `chrome://extensions/shortcuts`.
- Дополнительно `Ctrl+PrintScreen` ловится best-effort в content script, когда клавиша доходит до страницы: `PrintScreen` нельзя назначить командой Chrome (не поддерживается и требует `Ctrl`/`Alt`).
- Пользователь освобождает `Ctrl+PrintScreen` в системе, если её занимает DE (Ubuntu/GNOME). Если DE перехватывает клавишу — запуск по ней не сработает, это ограничение платформы.
- Системный helper и произвольный глобальный hotkey не входят в эту задачу. Резерв — клик по иконке расширения.

## Вопросы для груминга

- Целевой сценарий — только при открытом и активном Chrome или из любого приложения?
- Нужно ли поддерживать только Ubuntu GNOME или другие DE и Linux-дистрибутивы?
- Готов ли пользователь вручную отключать конфликтующий системный shortcut?
- Нужен ли отдельный нативный helper, если запуск из любого приложения является обязательным?
- Как показывать конфликт и подсказку о переназначении в `chrome://extensions/shortcuts`?

## Критерии приёмки

- В документации и интерфейсе явно разделены режимы «в фокусе браузера» и «глобальный».
- Поддерживаемая комбинация запускает Snapmark без конфликтов, когда Chrome имеет фокус.
- При конфликте с ОС приложение не обещает невозможного перехвата и показывает понятную инструкцию по смене сочетания.
- Если выбран нативный helper, он устанавливается и отключается безопасно, а сценарий покрыт тестами на целевой платформе.
