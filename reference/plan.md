## Результат

Snapmark работает прямо поверх текущей страницы. Хоткей или кнопка расширения сначала включает
выделение на живом DOM — снимка в этот момент ещё нет. После `pointerup` расширение единственный раз
фиксирует viewport без собственных визуальных элементов, вырезает выбранный участок с учётом DPR и
замораживает его ровно на исходных экранных координатах.

Редактор и панели находятся в изолированном Shadow DOM. Остальная страница остаётся видна под затемнением
12% и лёгким blur 3 px, но её scroll, мышь и клавиатура временно заблокированы. Copy и Save As экспортируют только выбранный
фрагмент. Закрытие полностью возвращает исходные стили и управление странице.

Отдельное окно — только технический fallback для поверхностей, куда Chrome действительно запрещает
внедрять content script: `chrome://`, Chrome Web Store, встроенный PDF viewer и подобные страницы.

## Строгая последовательность запуска

1. Service worker отправляет существующему content script `SNAPMARK_BEGIN_SELECTION`.
2. Если получатель отсутствует, service worker находит локальный content bundle в manifest и внедряет его
   через `chrome.scripting.executeScript`.
3. После инъекции команда запуска повторяется и её ответ проверяется.
4. Только при запрете инъекции выполняется один захват и открывается fallback-окно с объяснением причины.
5. Если запрещены и overlay, и захват, отдельное пустое окно не создаётся: action badge показывает `!`,
   а title содержит понятную ошибку.

Обычные HTTP/HTTPS-вкладки, в том числе открытые до установки или перезагрузки расширения, должны пройти
через шаги 1–3 и остаться в той же вкладке.

## Inline-сценарий

1. `Ctrl+Shift+S` или клик по action монтирует прозрачный блокирующий Shadow DOM overlay.
2. Пользователь тянет синюю рамку по живой странице. До окончания жеста `captureVisibleTab` не вызывается.
3. После `pointerup` рамка, подсказка и курсор Snapmark скрываются, а прозрачный blocker остаётся.
4. Через два animation frame content script запрашивает `SNAPMARK_CAPTURE_REGION`; service worker делает
   ровно один `captureVisibleTab`.
5. Crop вычисляется как `CSS-координата × image/viewport scale` отдельно по X/Y. Это покрывает DPR и zoom.
6. Canvas выбранного фрагмента размещается fixed по исходному `left/top/width/height`; повторного захвата
   при resize нет.
7. Верхняя панель располагается над фрагментом, левая — слева. У края viewport они переносятся внутрь.
8. Четыре внешние маски дают затемнение 12%, не накладывая его на замороженный фрагмент.
9. При закрытии host удаляется, обработчики снимаются, scroll и временные inline-стили восстанавливаются.

## Редактор

- Инструменты: select, arrow, rectangle, ellipse, pencil и text.
- Аннотации по умолчанию ярко-коралловые `#FF4D2E` с автоматическим светлым или тёмным halo.
- Синий используется только для UI-состояний: active/focus, рамки захвата, bbox и handles.
- Для прямоугольника и овала доступна заливка с opacity около 12%.
- Поддерживаются выбор, перемещение, изменение размеров, удаление, undo/redo.
- После новой фигуры открывается поле комментария. Пустая подпись не удаляет фигуру. После применения
  подпись остаётся отдельной перетаскиваемой плашкой с коралловой линией-связью и точкой-якорем на своей фигуре.
  Её можно тянуть прямо за плашку; выбранная подпись получает синюю пунктирную рамку и девять явных handles
  сеткой 3×3: восемь по краям меняют соответствующую сторону, центральный переносит карточку. Наведение на
  плашку и центр показывает `move`, на стороны — `ns-resize`/`ew-resize`, на углы — диагональный resize.
  Связь карточки с фигурой — коралловая пунктирная линия с пунктирным halo. Карточка переносит длинный текст
  и сохраняет свою ширину и высоту отдельно от фигуры.
- Все кнопки — локальные inline SVG Tabler Icons 3.46.0, 18×18 px, stroke 2 px, с `aria-label`,
  keyboard focus и tooltip. Emoji, буквы вместо иконок и внешние CDN не используются.
- Copy и Save стоят рядом. Save всегда вызывает системный диалог выбора имени и папки.
- Отмена Save As или ошибка экспорта не закрывает редактор и не теряет работу.

## Клавиатура

- В поле комментария `Enter` применяет текст и возвращает управление редактору.
- `Shift+Enter` и `Ctrl+Enter` добавляют новую строку.
- Клик вне поля также применяет текст.
- `Esc` отменяет только текущую правку: новая фигура остаётся без подписи, существующий текст
  восстанавливается.
- В поле есть SVG-галочка `Готово · Enter` и подсказка `Новая строка · Shift/Ctrl+Enter`.
- Когда поле не активно, следующий `Enter` копирует PNG; настройка может закрыть overlay после успеха.
- `Ctrl+S` открывает системный Save As; `Ctrl+Z` — undo, `Ctrl+Shift+Z` и `Ctrl+Y` — redo; `Delete` удаляет выбранное.
- `V A R O P T` переключают инструменты.

## Архитектура MV3

```text
service worker (background.ts)
  ├─ begin: send → inject if absent → retry
  ├─ SNAPMARK_CAPTURE_REGION → один captureVisibleTab
  ├─ save → chrome.downloads.download({ saveAs: true })
  ├─ copy fallback → offscreen document
  └─ prohibited surface → fallback window or badge error

content script (content.ts + editor/)
  ├─ live selection in Shadow DOM; page locked
  ├─ hide visuals → request capture
  ├─ DPR-aware crop → canvas fixed at original region
  ├─ annotation editor and export
  └─ cleanup restores page exactly

fallback page (editor.html)
  └─ same tools and export, plus reason banner
```

Permissions: `activeTab`, `scripting`, `storage`, `commands`, `downloads`, `offscreen`,
`clipboardWrite`; content match for ordinary HTTP/HTTPS pages.

## Fallback

- Fallback визуально и функционально повторяет тот же редактор, но объясняет, почему понадобилось окно.
- Временная ошибка первого `sendMessage` сама по себе не является основанием для fallback: обязательны
  попытка инъекции и повторный запуск.
- Если `captureVisibleTab` также запрещён, остаётся текущая вкладка и появляется action badge `!`.

## Проверка и критерии приёмки

- На обычной странице не создаются новые вкладки или окна.
- До `pointerup` нет захвата и canvas; после него есть ровно один запрос захвата.
- В кадр не попадают рамка, подсказка и панели Snapmark.
- При DPR 1, 1.25, 1.5 и 2 crop совпадает с CSS-областью; browser zoom учитывается фактическим scale снимка.
- Canvas остаётся на исходных координатах; панели не попадают в экспорт.
- Внешняя страница видна под 12% маской и не принимает scroll/click/keyboard; после close состояние восстановлено.
- Вкладка, открытая до установки расширения, получает content script через динамическую инъекцию.
- Copy, Save, Enter/Esc, undo/redo и два типа многострочного ввода не регрессируют.
- На запрещённой странице используется fallback или badge error — никогда пустое окно.
- SVG валиден и одинаково читается в PNG; `08/e` показывают синий UI и коралловые аннотации разными слоями.
- Выполняется не более двух визуальных браузерных циклов; сохраняются два QA-примера и машинный отчёт.

## Допущения и границы текущей версии

- Overlay — обязательный основной режим, fallback — крайний технический путь.
- Viewport фиксируется только после завершения выделения; resize не инициирует новый capture.
- Страница на время работы полностью заблокирована.
- PrintScreen не объявляется через `chrome.commands`; основной хоткей — `Ctrl+Shift+S`, переназначаемый в Chrome.
- Расширенные arrow presets, отдельное перетаскивание подписи и стили `tag/numbered` остаются следующими
  итерациями и не блокируют базовый overlay-first сценарий.
